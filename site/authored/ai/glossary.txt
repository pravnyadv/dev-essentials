# One term per line: `term [alias, alias] | plain-language definition`. Matching is case-insensitive on whole words.
# The build lists each term on the topic pages that use it. Keep definitions to one or two sentences for a newcomer.
token [tokens] | A piece of text the model reads and writes, usually a word or part of a word. About 4 characters of English on average.
tokenizer [tokenization] | The program that splits text into tokens and maps each one to an integer id.
context window | The maximum number of tokens a model can look at in one call: your prompt, the conversation, tool results and the answer together.
parameter [parameters] | One learned number inside a model. Modern models have billions of them. Training adjusts them.
weights [weight, open-weight] | The learned numbers that define a trained model. A model whose weights are published is called open-weight.
prompt [prompts] | The input text you give a model, including instructions, examples and data.
system prompt | Standing instructions placed at the start of every call that set the model's role and rules.
LLM [LLMs, large language model] | Large language model: a neural network trained on huge amounts of text to predict the next token.
neural network | A function built from layers of simple units (neurons) whose weights are learned from data.
neuron [neurons] | One unit in a network: it multiplies inputs by weights, adds a bias and applies an activation function.
activation function [activation] | A simple curve such as ReLU applied after a neuron's sum. It lets stacked layers represent complex functions.
ReLU | An activation function that outputs the input if positive, otherwise 0.
embedding [embeddings] | A list of numbers that represents the meaning of a piece of text or an image, so similar things sit close together.
vector [vectors] | An ordered list of numbers. Embeddings and model activations are vectors.
matrix [matrices] | A grid of numbers. Multiplying a vector by a matrix transforms it. Model layers are mostly matrices.
tensor [tensors] | A multi-dimensional array of numbers. The basic data type of deep learning libraries.
dot product | Multiply matching entries and add. Positive when the arrows lean the same way, zero at a right angle, negative when they lean apart; the size also grows with vector length.
cosine similarity | A score from -1 to 1 for how much two vectors point the same way, ignoring their length.
softmax | A function that turns a list of scores into probabilities that add up to 1.
logits | The raw scores a model produces for each possible next token, before softmax.
temperature | A setting that sharpens or flattens the probabilities before sampling. Low is predictable, high is varied.
top-p | A sampling rule that only considers the smallest set of tokens whose probabilities add up to p.
sampling | Picking the next token at random according to the model's probabilities.
inference | Running a trained model to produce output, as opposed to training it.
training | Adjusting a model's parameters on data so its predictions improve.
pretraining | The first, large training stage: predict the next token across a huge amount of text.
fine-tuning [fine-tune, SFT] | Further training on a smaller, targeted set of examples to change behavior or style.
RLHF | Reinforcement learning from human feedback: tune a model toward answers that people rate higher.
reinforcement learning [RL] | Learning by trial and error: take actions, get rewards, and favor what earned reward.
reward | A number that says how good an outcome was. RL tries to maximize it.
policy | A rule for choosing actions. In a language model, the model itself is the policy.
loss | A number measuring how wrong the model's output is. Training tries to reduce it.
cross-entropy | The standard loss for next-token prediction: minus the log of the probability given to the correct token.
gradient [gradients] | The direction and rate at which the loss changes when each parameter changes. Training steps against it.
gradient descent | Repeatedly nudging parameters opposite to the gradient to reduce the loss.
learning rate | How big each gradient descent step is. In Q-learning it is the share of the gap to the new estimate closed per update.
backpropagation [backprop] | The method that computes the gradient for every parameter by applying the chain rule backward through the network.
optimizer | The algorithm that turns gradients into parameter updates, such as SGD or Adam.
Adam [AdamW] | The most common optimizer. It smooths gradients and adapts the step size for each parameter.
overfitting | When a model memorizes training data and does worse on new data.
GPU [GPUs] | Graphics processing unit. A chip with thousands of cores, ideal for the matrix math in AI.
batch | A group of examples processed together in one step.
epoch | One full pass through the training data.
transformer | The neural network architecture behind modern language models. It uses attention to relate every token to the others.
attention | The mechanism that lets each token weigh all earlier tokens by relevance when computing its next representation.
self-attention | Attention where the tokens attend to other tokens in the same sequence.
KV cache | Stored keys and values of earlier tokens, reused during generation so each new token is cheap to compute.
RoPE | Rotary position embedding: a way to tell the model where each token sits by rotating its query and key vectors.
mixture of experts [MoE] | A design with many specialist sub-networks where a router uses only a few per token, so compute is far less than the total size.
quantization [quantized] | Storing weights with fewer bits (for example 4 instead of 16) to save memory at a small quality cost.
distillation | Training a small model to imitate a larger one.
LoRA [QLoRA] | A cheap fine-tuning method that freezes the model and learns small add-on matrices. QLoRA also stores the base in 4-bit.
benchmark [benchmarks] | A fixed test with a score used to compare models.
hallucination [hallucinations, hallucinate] | A confident answer that is not supported by the model's knowledge or the provided sources.
knowledge cutoff | The date after which the model has seen no training data.
in-context learning | A model picking up a task from examples inside the prompt, without any retraining.
few-shot | Giving a few worked examples in the prompt.
chain of thought [chain-of-thought] | Having the model write out intermediate reasoning steps before the final answer.
reasoning model | A model trained to think at length, often with RL, before answering.
multimodal | Handling more than one kind of data, such as text, images and audio.
structured output | Model output that follows a schema, such as valid JSON with fixed fields.
JSON | A text format for structured data: keys and values in braces, like {"name": "Ada"}.
schema | A description of the shape of data: which fields exist and what types they have.
API | Application programming interface: a way for one program to call another, usually over HTTP.
SDK | Software development kit: a library that wraps an API for a programming language.
tool use [function calling, tool call, tool calls] | The model asks your program to run a function and reads the result.
tool [tools] | A function the model can ask your program to run, described by a name, description and argument schema.
MCP | Model Context Protocol: a standard for plugging tools and data into AI apps.
agent [agents, agentic] | A model run in a loop that chooses its own tools and steps until the task is done.
workflow [workflows] | A fixed sequence of steps written in code, with model calls at set points.
subagent [subagents] | A helper agent started by another agent for a focused job, with its own context.
orchestrator | The component, often a model, that splits work and delegates it to workers.
harness | Everything around the model that makes it an agent: prompts, tools, rules, sandboxes, hooks, memory and checks.
hook [hooks] | A script the harness runs automatically at a fixed point, such as before a tool call. It enforces rules in code.
skill [skills] | A folder of instructions and scripts an agent loads only when a task needs it.
sandbox | A restricted environment where code can run with limited access to files and the network.
compaction | Summarizing older conversation so a long task fits in the context window.
context engineering | Deciding what goes into the model's context window, and when.
prompt injection | Untrusted text that contains instructions the model follows, such as a web page telling it to leak data.
guardrail [guardrails] | A rule or check that limits what a system may do or output.
human-in-the-loop | A design where a person approves risky steps.
RAG [retrieval-augmented generation] | Retrieval-augmented generation: look up relevant text first, then give it to the model to answer from.
retrieval | Finding the most relevant pieces of text for a query.
chunk [chunks, chunking] | A small piece of a document, sized for indexing and retrieval.
vector database [vector store] | A database that stores embeddings and finds the nearest ones quickly.
BM25 | A classic keyword scoring method that ranks documents by matching terms.
hybrid search | Combining keyword search and vector search.
reranker [reranking] | A second model that rescores a short list of search results by reading query and passage together.
eval [evals, evaluation] | A repeatable test of AI output quality, run before and after every change.
trace [traces, tracing] | The full record of one run: inputs, model calls, tool calls, outputs, timing and cost.
observability | Being able to see what your system did, through logs, traces and metrics.
LLM-as-judge [LLM as judge] | Using a model to grade another model's output against a rubric.
trajectory | The sequence of steps and tool calls an agent took, not just its final answer.
rubric | A written list of criteria used to grade an output.
CI [CI/CD] | Continuous integration: automatically running tests on every code change. CD deploys passing changes.
Docker | A tool that packages software and its dependencies into a portable container.
repo [repos, repository] | Repository: a project folder tracked by git, usually hosted on GitHub.
git | The standard tool for tracking changes to code.
worktree [worktrees] | A second checked-out copy of a git repository on its own branch in its own folder.
CLAUDE.md | A file at a repo root that Claude Code reads at the start of every session. AGENTS.md is the shared equivalent.
AGENTS.md | A shared convention for a repo file with instructions for coding agents.
vibe coding | Building software by prompting and accepting results with little review.
Hugging Face | A hub for sharing open models, datasets and demos, and the maker of widely used libraries.
open source | Software whose code is public and can be reused under a license.
diffusion model [diffusion] | An image generator trained to remove noise step by step. Generation starts from pure noise.
CNN [convolutional neural network] | A network that slides small filters over an image to detect edges, shapes and objects.
AGI | Artificial general intelligence: a loosely defined label for AI as capable as people across most tasks. There is no agreed test.
DPO | Direct preference optimization: a simpler way to tune a model toward answers people prefer, without a separate reward model.
PPO | Proximal policy optimization: a reinforcement learning method that limits how far each update can move the model.
GRPO | Group relative policy optimization: a reinforcement learning method that scores each answer against the other answers sampled for the same prompt.
HNSW | A graph-based index that finds approximate nearest neighbors quickly by jumping through layers of connections.
ANN [approximate nearest neighbor] | Search that returns vectors that are almost always the closest ones, much faster than checking every vector.
OAuth | A standard way to let an app act for you without giving it your password.
stdio | Standard input and output: how a local program talks to the program that started it, used by local MCP servers.
latency | The time you wait for a response.
backoff [exponential backoff] | Waiting longer after each failed attempt before retrying, for example 1, 2, then 4 seconds.
jitter | A little randomness added to retry waits so many clients do not retry at the same moment.
hyperparameter [hyperparameters] | A setting you choose before training, such as the learning rate, rather than a value the model learns.
MRR | Mean reciprocal rank: the average of 1 divided by the rank of the first correct result. Higher is better.
F1 | A score that combines precision (how many flagged items were right) and recall (how many right items were found).
prefill | The first stage of generation, where the model reads the whole prompt at once.
decode | The second stage of generation, where the model writes one token at a time.
context rot | Answers getting worse as the input gets longer, even on simple tasks.
cross-encoder | A model that reads a query and a passage together and scores how relevant the passage is. Used for reranking.
validation set | Data held out from training and used to tune choices and check that the model generalizes.
SIGTERM | A signal that asks a program to shut down cleanly.
OCR | Optical character recognition: turning an image of text into real text.
BPE | Byte-pair encoding: a common way tokenizers build their vocabulary by merging frequent pairs of characters.
logarithm [logarithms, log] | The power you raise a base to in order to get a number. log base 2 of 8 is 3 because 2 to the power 3 is 8.
nats | The unit of information when you use the natural logarithm. Bits use log base 2.
SWE-bench | A benchmark that scores coding agents on real GitHub issues from open-source projects.
GraphRAG | Retrieval that first builds a graph of entities and relations, for questions that span many documents.
reciprocal rank fusion [RRF] | A way to merge two ranked result lists by adding 1 / (k + rank) for each list.
A2A | Agent2Agent: a protocol for agents from different makers to find each other and exchange tasks.
collaborative filtering | Recommending items by finding people with similar past choices: if they liked it, you probably will too.
recommender [recommenders, recommendation system] | A system that suggests items such as videos or products to each user.
cold start | The problem that a new user or item has no history, so a recommender has nothing to match.
class imbalance | When one outcome is far rarer than the other, such as 100 frauds in 100,000 payments. Plain accuracy then misleads.
anomaly detection | Finding cases that look unlike normal ones, often without labeled examples of the bad kind.
precision | Of the cases a system flagged, the share that were truly positive.
recall | Of the truly positive cases, the share the system found.
forecasting | Predicting a future number, such as sales, from past values.
computer vision | Getting models to work with images and video: classifying, locating objects and reading text.
speech recognition [ASR] | Turning spoken audio into text.
text-to-speech [TTS] | Turning written text into spoken audio.
word error rate [WER] | Speech recognition accuracy: substitutions, deletions and insertions divided by the number of true words.
sim-to-real | The gap between a robot trained in simulation and the same robot in the real world.
data drift | Real-world inputs slowly changing from what a system was tested on, so quality falls with no code change.
ROI | Return on investment: what a project gains compared with what it costs.
baseline | A simple method, such as "same as last week", that any model must beat to be worth its cost. In regression testing, the baseline is the pass rate and saved outputs of the last version you accepted, which every change is compared against.
shadow mode | Running a new system beside people on real cases without acting on its output, so you can compare it with their decisions at no risk.
A/B test | Showing two versions to different groups of real users and comparing a measured result, such as clicks or sales.
object detection | A vision task that finds each object in an image and draws a box around it.
segmentation | A vision task that labels every pixel by which object it belongs to.
deepfake [deepfakes] | A realistic fake image, video or voice made with AI to look like a real person or event.
C2PA | A standard for attaching a signed record of where an image or video came from and how it was edited.
allowlist | A list of the only actions or sites something is permitted to use. Everything not on it is refused.
least privilege | Giving a person or program only the access it needs for the job and nothing more.
IoU [intersection over union] | A score for a predicted box: the overlap area divided by the combined area of the predicted and true boxes. 1 is a perfect match, 0 is no overlap.
calibration | Whether a model's confidence matches how often it is right. A well calibrated model is right about 90 percent of the time when it says 0.9.
leakage [data leakage] | When a feature or test example contains information that would not be known at prediction time, so scores look better than real use.
metadata | Extra labels stored with a document or chunk, such as its title, date or country, which let you filter results.
vocabulary | The full list of pieces (tokens) a model knows how to read and write.
stop token | A special marker the model writes to say its answer is finished.
diff | The list of lines a change added and removed, shown against the old version.
deterministic | Giving the same output every time for the same input.
LLM judge [judge, calibrated judge] | A second model prompt that grades an answer against a rubric. Calibrated means you checked its grades against your own on a sample.
smoke test | A few quick checks right after a deploy that prove the app starts and answers.
SQL injection [injection] | An attack where a value pasted into a database command is treated as part of the command and runs, instead of being treated as plain data.
parameterized query [parameterized queries] | A database command sent separately from its values, so the values are only ever treated as data and can never change the command.
test set | A fixed batch of example inputs, each with a known good answer, that you run every change against.
classifier | A model or program that puts an input into one of a fixed list of categories, such as "safe" or "harassment".
context anxiety | A habit of some models to rush and wrap up as they near the context limit.
feedback loop | When a system's output changes the data it learns from next, such as a recommender that only shows past clicks and so only collects clicks on those items.
standard error [standard errors] | How much a measured number, such as a click rate difference or a pass rate, would wobble by pure chance if you repeated the test. A gap smaller than about two standard errors could easily be luck, and with 30 test cases a pass rate near 73 percent can easily move by about 8 points.
trend | A steady rise or fall in a series over time.
season [seasonal] | A shape in a series that repeats on a schedule, such as busy weekends.
threshold | The score above which a case is flagged.
streaming [stream, streams] | Sending partial results onward as soon as they exist instead of waiting for the whole result.
bias | Systematic unfairness in a model's results, usually learned from skewed or one-sided data. In a layer, bias is also one extra learned number added to each output after the matrix multiply, which shifts the result up or down.
proxy [proxies, stand-in] | An innocent-looking input, such as a postcode, that tracks a protected group closely enough to carry the same information.
ImageNet | A benchmark of over a million labelled photos sorted into 1,000 categories, used to compare image recognition models.
GAN [GANs, generative adversarial network, generative adversarial networks] | A pair of networks trained against each other: a generator makes fakes and a discriminator tries to spot them.
discriminator | The network in a GAN that judges whether an image is real or generated.
provenance | A record of where an image came from and how it was made, and whether you have the right to use it.
Q-learning | A reinforcement learning method that keeps a score for each action in each situation and nudges it toward reward plus the best score of the next situation.
CASP [CASP14] | A blind contest run every two years where teams predict protein structures that labs have solved but not yet published.
amino acid [amino acids] | One of the small building blocks that are chained together to make a protein.
log-softmax | The logarithm of the softmax output, computed directly from the model's raw scores so tiny probabilities never round to zero.
floating point number [float] | The way computers store decimal numbers in a fixed number of bits, which limits how small or large a number can be.
derivative | How much a function's output changes when you nudge its input a tiny bit, which is also the slope of its curve at that point.
slope | How steeply a curve rises for each step to the right at a given point. The slope of a function at a point is its derivative.
vanishing gradient | When the slopes multiplied through many layers shrink toward zero, so early layers get almost no learning signal.
mini-batch [mini-batches, minibatch] | A small random sample of the training data used for one step of training, instead of the whole dataset.
held-out [held-out data, held-out loss, held-out group] | Examples kept out of training and tuning and used only to check whether the model works on data it has not seen.
prompt caching [prompt cache] | A provider feature that reuses the already-processed start of a prompt when the next request begins with the same text, so repeated long inputs cost less and return faster.
modality | The kind of input or output a model handles, such as text, images or audio.
server-sent events [SSE] | A plain HTTP connection the server keeps open and writes small named events to, used to stream a model's answer piece by piece.
rate limit [rate limits, 429] | A cap on how many requests or tokens you can send per minute. Going over it returns a 429 error, and the fix is to wait and retry.
pin | To lock a server to one exact version so an update cannot change it unseen.
exfiltration | Sending stolen data out to an attacker.
seed | A number that fixes the random starting noise, so the same prompt and seed give the same image.
alt text | A short description of an image for people who cannot see it, read by screen readers.
pull request [PR, pull requests] | A proposed set of code changes that teammates can review before it is merged.
memory file [memory files] | A text file in your repo, such as CLAUDE.md, that a coding agent reads at the start of every session.
exit code | A small number a script ends with. 0 means it worked and anything else means a problem. Claude Code treats 2 from a before-the-action hook as a signal to block the action.
remotion | A framework for writing video as code: you write React components and it draws one picture per frame number.
react | A JavaScript library where a component is a function that returns a picture of the interface.
still [stills] | A single frame of a video saved as an image.
easing | A curve that makes motion speed up or slow down instead of moving at a constant rate.
regression | Predicting a number, such as a price. In testing, a regression is a change that breaks something that used to work, such as a provider updating a model so a previously passing test case now fails.
pass^k [pass-hat-k] | The chance that an agent passes every one of k runs of a task; it falls quickly as k grows even when a single run usually passes.
jailbreaking | Typing tricks into a chat yourself to make a model do something it should not.
protected attribute [protected attributes] | A trait such as gender, age or ethnicity that people should not be treated worse for.
moderation | An automatic check that flags text containing harmful content, such as hate, self-harm or violence, so you can block it or send it to a person.
red-team [red-teaming] | Deliberately attacking your own system, with people and scripts, to find the ways it breaks before real users do.
copyright | The legal right to control who can copy and sell a piece of work.
reverse image search | Uploading a picture to a search engine such as Google Lens or TinEye to list other places the same image appears.
delimiter [delimiters] | A marker such as ### or triple quotes that fences off one part of a prompt, like pasted data, from the instructions.
orchestration [orchestrate] | Coordinating several agents or models so each handles part of a task, including which one runs when and how work is handed between them. It is code that decides which prompt, tool or model call happens next and keeps state between steps.
probabilistic | Giving possibly different outputs for the same input, because the result is sampled from likelihoods instead of computed by fixed rules.
staged files [staged] | In git, the files you have marked to be included in the next commit.
self-supervised learning | A kind of supervised learning where the answers come from the data itself, such as the next token in a text, so no human labeling is needed.
regularization | A penalty or constraint that stops a model from fitting every wiggle of the training data, so it generalizes better.
feature [features] | One input measurement the model reads, such as a house's area.
classification | Predicting a category, such as spam or not spam.
power law | A relationship where multiplying one quantity by a fixed factor multiplies another by a fixed factor, such as loss falling 15 percent for every 10 times more parameters.
post-training | Training done after the main text-prediction run, to shape how the model behaves, for example following instructions or preferring answers people rate well.
test-time compute [thinking tokens] | Extra work a model spends while answering (for example writing out reasoning steps) instead of during training, trading time and cost for accuracy on hard problems.
reward model | A separate network trained on human choices between two answers, used to score how much a person would like a model's answer.
sycophancy | A habit of agreeing with the user even when the user is wrong, often learned because agreeable answers get rated well.
non-deterministic | Giving different outputs for the same input. Run a model twice on one prompt and you may get two different answers.
feed-forward [feed-forward network] | A small neural network applied to each token's vector on its own, after attention has mixed in information from other tokens.
model card | A short document a lab publishes with a model, listing what it was trained for, how it was tested and its known limits.
head [heads, attention head] | One of several attention calculations that run side by side in a layer, each free to look for a different pattern in the text.
bigram [bigram model] | A model that predicts the next character using only the one before it, so it is just a table of counts.
rank | How many independent directions a change to a layer can move along. A rank-8 LoRA update can move the layer along 8 directions.
advantage | A score for how much better an answer was than the reference, such as the group's average reward. Positive means reinforce it, negative means discourage it.
value model [critic] | A second model that PPO trains to guess how good a situation is, so advantages can be computed. GRPO removes it by using the group's average reward instead.
perplexity | A score for how surprised a model is by real text. Lower is better, so a jump up after quantizing means damage.
memory bandwidth | How many gigabytes per second a card can read from its own memory.
continuous batching | A serving trick where a new request joins a batch that is already running instead of waiting for the whole batch to finish.
paged attention [PagedAttention] | A way to store the KV cache in small fixed blocks so memory is not wasted on gaps.
speculative decoding | A small, fast model guesses the next few tokens and the large model checks all of them in one pass, keeping the ones it agrees with.
GGUF | A file format for running quantized models locally, used by llama.cpp.
AWQ [GPTQ] | Quantization methods aimed at serving models on GPUs.
context cache | Extra memory a model uses to remember the text so far, so it grows as the prompt and conversation get longer.
swap | Disk space the system uses as overflow memory when RAM is full, far slower than RAM.
migration | A scripted change to a database's tables or columns, run when you deploy new code that needs a different shape of data.
staging | A private copy of your app, with its own keys and spend cap, where you test a release before it reaches real users.
Agent Skills | A folder holding a SKILL.md file with instructions, plus optional scripts, that an agent loads only when a task needs it.
agent card | A short description an A2A agent publishes about what it can do, which is how other agents discover it.
effort [thinking effort, reasoning effort] | A setting such as low, medium or high that hints how long a reasoning model should think before answering. It is guidance, not a hard limit.
thinking budget [budget] | A ceiling on how many thinking tokens a reasoning model may use for one answer.
handoff [handoffs] | A short written note that carries the goal, what is done, what was tried and what is next into a fresh context, or the act of one agent passing the task to another agent better suited to the next part.
reset | Starting a fresh context that holds only a written handoff note, clearing out accumulated clutter and confusion.
normalize [normalizing, normalized] | Divide a vector by its own length so the new length is 1. For example [3, 4] has length 5, so it becomes [0.6, 0.8].
text layer | The characters stored inside a PDF along with their positions on the page. A scan has no text layer, only an image of the page.
sharding [shard, sharded] | Splitting a large set of data across several machines so each one holds only a part.
base URL | The web address your client sends API requests to. Changing it points the same code at a different provider.
router | A service such as OpenRouter that offers one API for many models from different providers, with fallback when one goes down.
agent loop | The cycle of calling the model, running any tool it asks for, adding the result and repeating until it gives a final answer.
checkpoint | A saved copy of an agent's state after a step, so a restart can resume from it instead of starting over.
